# CONTENT_PRODUCTION｜「もしもの続き」の作り方

## 1. シリーズの設定【確定】
- 「もしも◯◯したら？」の思考実験を、時間の流れに沿って実況する縦ショート。
- **見た目はマイクラ風3D（ボクセル）だけ**（11/8決定。2Dは【旧設定】）。主人公「僕」＝オレンジの服・青いズボン・黒髪の四角いキャラ。
- 題材は **コメントのリクエストから「一番見応えのあるもの」** を選ぶ（11/8決定）。**16本目以降はアリがテーマ【確定 11/9】**。ほかの未使用リクエスト：鉄塊、木、野球ボール（車・すいか・消しゴム・摩擦は制作済み）。
- 画面の文字（GitHubの仕組みが自動で入れる）：上に「もしもの続き」と進捗の点、黄色の時刻バッジ、中央に見出し（12文字以内）、下に字幕の帯。

## 2. 台本のルール
- 形式：`channels/moshimo/queue/<台本ID>.json`（`sample.json` と同じ形）。台本IDは日付（例 20261117）。queue・used にあるIDとかぶらせない。
- 1本 40〜55秒・7〜9シーン（パロディ回は例外で長め可）。
- **重力の型**【確定 11/1】：
  1. 1コマ目は明るく、派手な場面から（何が起きるか音なしでも分かる）
  2. 最初の約4秒で「予想を否定」する（見出しに赤い×が出る演出。`draw_x` / XFRAC で声の「いいえ」に合わせる）
  3. 最後は短く。問いかけは1文だけ（最後の問いかけの場面で毎回大きく離脱する）
- 科学的に正しく。確かでないことは「〜と考えられています」。条件つきの数字には条件を書く。
- 締め：「次は、◯◯？◯◯？コメントで教えてください。」のように**次の候補を見せて**コメントを誘う。
- 固有名詞は正しく読ませる：画面の字幕（narration）は漢字、読み上げ（lines の text）はひらがな【確定 11/9】。

## 3. 映像のルール（マイクラ風3D）
- 1080×1920・30fps・libx264・yuv420p。背景クリップは**文字なし**で作る。
- **カメラは最初から最後まで動かし続ける**。大きな寄り（ズームアップ）と引き（ズームダウン）を場面ごとに入れる【確定 11/7〜】。穴・すいかの回で効果が出た。
- 1コマ目に「目に見える物」をはっきり映す（摩擦の回は人が立っているだけで2時間で止まった→11/9の仮説【暫定】）。
- 大事なもの（顔）は **見出し（画面の高さ36〜43%）と字幕（68%から下）の間** に置く。静止画に赤線を引いて確認する。
- 参考動画（11/9に受け取った画面録画）の分析：1〜2秒ごとに画角が変わる。→ 1場面の中で2〜3回カットを切りかえる（顔アップ／相手の目線／肩ごし／俯瞰／あおり／小物の超アップ／ななめ）【確定 11/9】。
- クリップの長さ＝(読み上げ文字数×0.135＋0.3)×0.9 秒が目安。声のほうが長いと自動でゆっくり再生される。

## 4. 音のルール
- 声：VOICEVOX。ナレーター＝青山龍星（13）。会話がある回は 四国めたん ノーマル（2）・白上虎太郎 ふつう（12）を併用（`lines` で話者を指定）。
- **BGMは最初から最後まで一定の音量。声や効果音のときに下げない**【確定 11/8・11/9再確認】。強調したい場面だけ下げてもよいが、細かい調整はいらない（ダッキングは【旧設定】）。`moshimo_tools/mix.py` で「声より12dB小さい」一定の音量にして、最後に -14 LUFS にそろえる。
- 音はシンプルに【確定 11/2】：曲を止める・無音を挟む演出は【却下】（聞きづらかった）。
- 効果音は映像の出来事のコマに合わせる（ずれると指摘される）。最初の「フッ」などは1秒くらい。
- BGMの大きさを参考動画に合わせる件は【未完了】（TikTokがコンテナから見られない。画面録画か、PCを連携して測る）。
- 音はすべてコードで作る（`taiyou_sound.py` の部品を使う。著作権の心配なし）。

## 5. パロディ回のルール【確定 11/9】
- **先にデザイン定義書を作ってから動画を作る**。2人のシーンを入れて、尺をしっかり使う。
- 定義書：Claude Docs「もしもの続き パロディ回 デザイン定義書」（https://claude.ai/artifact/4vKG2GvmtsQPeVytD4cFqR）と、シート画像 `channels/moshimo/design/kaguya/sheet1〜3.png`（添付の宇野カナタ等のシートと同じ形式）。
- 作品名・人物名・設定は使う。セリフはすべてオリジナル。概要欄に「※ファンによる非公式のパロディです。セリフはすべてオリジナルです。」
- **原作キャラクターの姿は描かない**（Claudeの方針。ゆうきは11/9に原作どおりの衣装で再現したいと希望したが、Claudeは対応できないと回答済み）。原作キャラは「声・画面の外から入る手・小物・目線カメラ」で出す。主人公は「僕」（オリジナルのデザイン、黄色い生徒会長の腕章）。

## 6. 作る手順（1本の流れ）
1. 台本を書いて queue に置く（パロディは定義書が先）。
2. 見本をコピーして `moshimo_tools/<題材>_voxel.py` を作る（`CLIPS`＝各場面の長さ、`frame(k,t)`＝場面k・t秒の絵）。
3. `python3 x.py stills 0:0.3,1:2.0,...` で静止画を出し、顔の位置・文字との重なりを確認して直す。
4. 書き出し：2プロセス同時（`python3 x.py 0,2,4 &` と `python3 x.py 1,3,5 &`、run_in_background で）。RS=3で約3秒/コマ、20場面の長尺はRS=4で約45分。
5. クリップを `channels/moshimo/clips/<台本ID>/01.mp4〜` に置いて commit・push → GitHub Actions（moshimo.yml）が自動で組み立て、Releases に short.mp4 と upload_memo.txt。
6. 新しいリリース（tag_name が変わったら完成）をダウンロード。
7. シーン開始時刻を測る（進捗の点の位置 or 見出しの変化）→ `<題材>_sound.py` で bgm.wav・sfx.wav → `python3 mix.py short.mp4 bgm.wav sfx.wav 完成.mp4 12`。
8. 完成版のコマを並べて目で確認（文字と顔の重なり・順番）。声の話者の違いは音の高さで確認できる。
9. SendUserFile で完成版を送り、タイトル・概要欄・Instagram/TikTokキャプション（ハッシュタグ5個）・AI表示の注意・投稿時刻を渡す。完成版は `finals/` にも保存する。

## 7. 投稿用の文章
- YouTube：タイトル（〜 #Shorts）＋概要欄（upload_memo.txt の【概要欄】＋全話者のクレジット）。
- Instagram/TikTok：問いかけ1行＋ハッシュタグ5個（#もしもの続き は4〜5個目）＋必要なら「※思考実験です」。
